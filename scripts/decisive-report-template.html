What was actually trained?

Randomized atomic fact bank→Text or learned tuple codec→Last 4 LongCat blocks + LoRA→Paths + answer + citations→Independent verifier

The memory codec independently encodes record ID, subject, object, sign, species, variant and source into one vector per record. It receives no question, answer or graph traversal. Text receives all seven fields explicitly. The pretrained backbone stays frozen. Text facts pass through all 14 blocks; memory vectors enter after block 10. Thus the memory condition has four contextual reader blocks after injection. This is an engineering constraint of this proof of concept, not a matched-depth test of every possible memory architecture.

What this can and cannot establish

This experiment tests fresh compositions of a fixed formal relation. Entity names are new world namespaces with a shared local vocabulary of 16 node aliases. Longer paths are held out from training. This is a harder composition test than recalling a stored answer, but it is not unseen biomedical terminology or scientific discovery.

All evidence is supplied completely. There is no retrieval-ranking advantage in either condition. The engineered codec plus LoRA differs from native EngramEdit and from a persistent clinical memory service. Replacing records at inference tests updateability without retraining; it does not implement autonomous ingestion, retention across tasks or learning new relation types. Record IDs and entity vocabularies are fixed to this bounded test. Two training seeds and 10–12 records per world do not establish production scalability, calibrated confidence, continuous evidence ingestion or rare-disease utility.

Biological associations do not automatically compose as causal signs. ARAX examples for Fabry disease, Gaucher disease and Rett syndrome remain exploratory evidence cases in the earlier report; they are not validated by these synthetic outcomes.

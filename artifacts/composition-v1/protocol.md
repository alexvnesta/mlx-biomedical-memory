# Composition after a working readout interface

This experiment continues the original memory-versus-text question only after
the repaired reader passes the frozen fresh-bank atomic gate. A failure to retain
readout is an interface failure, not evidence against reasoning with accessible
memory. No outputs from this experiment's final graph tests may select a model.

## Fixed interface, fair text control

Use the pinned LongCat native 4-bit backbone and the original seven-field,
one-vector-per-record codec. Initialize the memory condition from the repaired
BF16 checkpoint, SHA-256
`3d913d797cf7209590c88336a014ca44d6a6197fe422f2ecc92d01ef9f3bb3c1`.
Freeze every codec parameter during composition training. Adapt only its rank-16
LoRA reader (2,957,312 parameters). The text control starts from fresh rank-32
LoRA (5,914,624 parameters), with every fact written explicitly. It receives no
previous synthetic reasoning adapter, so the new query partition is meaningful.
Both use the existing formal graph prompt, full banks, identical training cases,
sample sequence, supervision, 1024 updates, learning rate 0.00003, clipping at 1,
and 16-update warmup. Each seed uses 64 atomic-only warmup updates and then one
atomic plus one reasoning example per update. Seeds are 2401 and 2402.
The predeclared common budget may extend to 2048 if the first seed's text
development proof score is below 24/48 or either condition misses the readout
gate. If the second seed reveals a gate failure at 1024, extend all conditions
and seeds to 2048. Keep earlier candidates eligible; never discard a better
already-scored checkpoint just because the budget increased. Failure of a
retention gate after that budget keeps the final test closed and requires a
public development amendment.

The memory condition's additional readout-alignment training is reported as an
extra cost; it is not silently credited as equal-budget reasoning training.
Text has more updated reader parameters. There is no retrieval-support advantage
for memory: both conditions receive all ten records. The codec never sees the
question, answer, path search, or graph-solver result.

## New data and structural holdout

Use the fresh corpus generated by `scripts/prepare_composition_experiment.py`:
384 reasoning plus 384 atomic training cases; 48 reasoning plus 64 atomic
development cases; 96 reasoning plus 64 atomic cases for each final stratum.
Training paths have depths one and two; structural tests have depths three and
four. Every bank has ten records and uses only trained record IDs F0–F9.

TRACE root/target alias pairs satisfy `(5*root + 3*target) % 8` in 2–7 for
training, 0 for development, and 1 for both final strata. Thus none of the final
query endpoint pairs is a supervised TRACE query during this experiment.
Individual bank edges are unrestricted: a held-out endpoint pair can occur as
an atomic edge in another world. Do not describe this as exclusion of every
atomic pair after reasoning training. World namespaces, complete banks, record
bindings, sources, contexts, signs, and target proofs are new.

UP, DOWN, BOTH and UNKNOWN are balanced. Both species and variant must match.
Directed-edge and context traps are present. The exact graph solver defines
synthetic gold; its perfect score is an execution oracle, not independent ARAX
validation. For UNKNOWN, a correct absence label and citations to all record IDs
do not constitute a positive path. Report positive-path cases and every path
depth separately.

## Training features and retention

Only training and development causal prefix features may be cached; never cache
final-test target states. For atomic training inputs, corrupt previous hidden
values with probability 0.5 while preserving token count, as in readout repair.
Keep true next-token labels and bank facts unchanged. Use exactly the same
corrupted decoder prefixes for memory and text. Reasoning targets are canonical
executed proof traces. Freeze the codec and verify its arrays before and after.

Save the best teacher-forced development-loss candidate and the final candidate.
Score both by actual generated development proofs and complete atomic readout.
Only positive-step candidates with at least 63/64 complete development records
are eligible. Among eligible candidates, select the most execution-valid
development proofs, then atomic accuracy, then lower NLL. Do not select an
untrained fallback or quietly drop a failed reader. If either condition fails
the retention gate, keep the final graph test closed and amend the development
recipe openly. A final-test atomic retention below 95% must also be reported as
an unqualified interface, rather than used to judge reasoning alone.

## Final comparison

Freeze selected checkpoints and case hashes before opening final generations.
Report answer-label accuracy, execution-valid proofs, positive paths, two-hop
proofs, depth-three/four proofs, and complete atomic retention. Include two
optimization seeds separately as well as pooled descriptive counts. They share
one repaired memory initialization, not independent readout-alignment fits.
Keep raw generations, prompts, facts, expected outputs, source snapshots, dataset
and checkpoint hashes in the public repository.

Apply the existing 64 single-field answer-changing interventions and record-ID
binding, row-order and masking controls. Both methods have the same information;
masking is an additional memory-only ablation. No timing advantage is inferred
from generations of different quality or length. The public comparison remains
a controlled synthetic test, not rare-disease discovery, clinical confidence,
or a service ranking against OpenEvidence or web search.

For the first 16 positive-path worlds in each final stratum, separately probe
every record in one canonical gold support set using READ questions. These
oracle-selected readout probes are never supplied to the TRACE generation.
Report support accessibility and a paired comparison on the common subset
where both readers decode all required records exactly. This distinguishes
available facts from successful search/composition; it does not give the primary
reasoner an oracle path or change the primary denominator.

## Resources

Serialize all large MLX processes using the kernel model lease. Cache the frozen
prefix once, then train the smaller tail to leave headroom for other sessions.
Keep the 27 GB Metal limit, stop on warning pressure or more than 2 GiB swap
growth, preserve checkpoints and other sessions, and verify process completion
before the next model load.
